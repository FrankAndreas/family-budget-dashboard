# Hub Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The budget app uses the family-hub login and takes its people from the hub; people removed there are
hidden here; a dependent child gets a read-only view of their own costs.

**Architecture:** `get_current_user_from_token` keeps its name and callers but reads the hub token (cookie
`hub_session` or Bearer), asks the hub (`hub.py`, cached 60 s) and refreshes the people from the hub
(`hub_people.py`, at most once a minute). `users.hub_id` links rows to hub people; `users.is_active` now means "the
hub lists this person for the app", so the existing inactive filters hide removed people.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, stdlib `urllib.request` (as `receipt_ai.py`), React 19/TS, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-30-hub-login-design.md` (Part B). Needs Part A in family-hub merged
(plan `family-hub/docs/superpowers/plans/2026-10-30-app-access.md`), including its ruling: `/api/session?app=` keeps
`valid` about the login and adds `access`.

## Global Constraints

- Invented people and data only; placeholders `<domain>`, `<NAS_IP>`; the repo is public.
- No token, cookie value or IBAN in any log line. The session cache key is `sha256(token)`, never the token.
- Hub unreachable → 503 `hub_unavailable`, never a login.
- Only an explicit parent action deletes a person's data; nothing the hub does deletes here.
- The receipt-mail path (`/api/v1/inbound`, own secret) is unchanged.
- New settings: `HUB_URL`, `HUB_PUBLIC_URL`, `HUB_APP_KEY` (default `budget`), `COOKIE_DOMAIN`.
- Checks from `backend/`: `../.superpowers/venv/bin/pytest -n auto -q -p no:warnings ../tests`, black, flake8
  (`--max-line-length=120 --extend-ignore=E203,W503`), mypy; frontend `npm run lint && npm run type-check && npm run build`;
  e2e `cd e2e && E2E_PYTHON=../.venv-e2e/bin/python npm test`.
- Component files export only components (lint rule). Migrations go 0022 → 0023.

## Review Focus

- Hub down while someone uses the app: every API call 503 `hub_unavailable`; the frontend shows a message with
  "Try again", no redirect loop. Test in Task 2 (backend) and Task 5 (frontend code path).
- Logged in to the hub but no access to `budget`: 403 `no_access`, a "no access" page, no redirect (would loop).
  Test in Task 2.
- Two requests at once on a fresh database both creating the same hub person: one row, no 500 (unique `hub_id`;
  retry the lookup after an IntegrityError). Test in Task 2.
- Two people swap names in the hub: the refresh renames without a unique-name error (rename via a temporary name
  or update in two passes). Test in Task 2.
- A removed person still appearing somewhere: owner choices, shares, splits, dashboard and report scopes, export —
  each list built from `models.User` must skip `is_active` false. Test in Task 3 (one list per kind).

### Task 1: Hub client

**Files:**
- Create: `backend/app/hub.py`
- Test: `tests/test_hub_client.py`

**Interfaces:**
- Produces:
  - `@dataclass(frozen=True) class HubPerson: id: int; name: str; role: str; color: str | None; language: str`
  - `class HubUnavailable(Exception)`
  - `fetch_session(token: str) -> tuple[HubPerson | None, bool]` — one HTTP call to
    `{HUB_URL}/api/session?app={HUB_APP_KEY}` with `Authorization: Bearer`; `(None, False)` when `valid` is false;
    `(person, access)` otherwise. Timeout 5 s; network error, timeout or non-200 → `HubUnavailable`.
  - `fetch_people(token: str) -> list[HubPerson]` — `GET {HUB_URL}/api/apps/{HUB_APP_KEY}/people`; 403/401 → `[]`;
    other errors → `HubUnavailable`.
  - `session(token: str) -> tuple[HubPerson | None, bool]` — `fetch_session` cached 60 s by `sha256(token)`
    (`CACHE_SECONDS = 60`; a lock around the dict; expired entries dropped on access).
  - `forget() -> None` — clears the cache (tests, logout).
  - Settings read at call time from the environment: `hub_url()`, `app_key()`, `public_url()`.

    header `X-Requested-With: budget` (else 403 `csrf`). `hub.session(token)`: no person → 401 `not_logged_in`;
    `access` false → 403 `no_access`; `HubUnavailable` → 503 `hub_unavailable`. Then `hub_people.refresh(db, token)`,
    the row by `hub_id` (none or inactive → `refresh(force=True)` once, then 403 `no_access`), language as today.
  - `auth.get_optional_user` keeps its contract on the new path.
  - `POST /api/v1/logout` → clears cookie `hub_session` (`Domain=COOKIE_DOMAIN` when set, path `/`), `hub.forget()`;
    open to everyone.
  - `GET /api/v1/hub` → `{"login_url": hub.public_url()}`; open to everyone.
  - Removed: `POST /login` (and `/token` if present), `POST /users`, `POST /members`, `POST /me/logout-everywhere`,
    `PATCH /me/language`, the startup Admin seed and its INITIAL PIN log, `SECRET_KEY`. `PUT /users/{id}` accepts only
    `has_allowance` and `privacy_enabled` (other fields → 422 via `extra="forbid"` on the schema).
  - `tests/fake_hub.FakeHub`: `add(name, role="PARENT", access=True) -> str` (returns the token `"tok-" + name`),
    `remove_access(name)`, `rename(old, new)`, `down: bool`; installed by an autouse fixture that monkeypatches
    `hub.fetch_session` / `hub.fetch_people` and calls `hub.forget()` / `hub_people.forget()`. Conftest seeds hub
    person `Admin` (PARENT). `helpers.register(client, username, role="PARENT", pin=..., by=None)` → `fake_hub.add`,
    returns `{"Authorization": "Bearer tok-<username>"}`; `login` returns the same headers for a known name, else 401.
